# 무용 온라인 멘토링 시스템 — 설치·운영 안내 (Ver.1.1, 2026-11-16)

ZOOM 대신 웹브라우저만으로 하는 1:1 화상 멘토링입니다. 별도 영상 서비스나 유료 서비스는 쓰지 않습니다.

- **멘토 ↔ 학생**: 영상·음성을 주고받습니다(브라우저끼리 직접 연결).
- **운영진(여러 명)·연구원**: 멘토링 중에는 두 사람 화면을 보기만 합니다. **멘토링 전(진행 중인 학생이 없을 때)**에는 「화면 등장」으로 자기 카메라·마이크를 켜고 학생 자리에 나와 멘토와 이야기할 수 있습니다(최대 3명). 학생 멘토링이 시작되면 자동으로 화면에서 내려갑니다.
- **다음 차례 학생 미리 연결**: 다음 차례 학생은 멘토·운영진과 **미리 연결**해 두되 영상·음성은 보내지 않다가, 차례가 되는 순간 바로 켜집니다(전환 1~2초).
- **녹화**: 녹화 담당 운영진 PC가 두 사람 화면을 **좌우로 합쳐** 학생별로 한 파일씩 저장합니다(운영진은 녹화되지 않음).

## 1. 주소

| 누가 | 주소 (3회차 예시) |
|---|---|
| 학생 | `https://mentoring.kartsproject.com/?r=3` |
| 멘토 | `https://mentoring.kartsproject.com/mentor.html?r=3` (멘토 코드 필요) |
| 운영진·연구원 | `https://mentoring.kartsproject.com/ops.html?r=3` (입장 화면에서 「운영진/연구원」 선택, 각 코드 필요) |
| 리허설 | 위 주소에서 `r=3` 대신 `r=test` |

도메인 연결 전에는 `https://kartsproject.github.io/mentoring/` 로 열립니다.

## 2. 구성

| 위치 | 내용 |
|---|---|
| GitHub `kartsproject/mentoring` | 화면 파일: `index.html`(학생), `mentor.html`, `ops.html`, `meet.js`(연결), `recorder.js`(녹화), `config.js`(설정), `style.css` |
| `apps-script/Code.gs` | 연결 관문(시그널링). 비밀값이 들어 있지 않아 저장소에 올려 두었습니다 |
| 구글 시트 「무용 온라인멘토링」 | 탭 「명단」(회차·순서·시작·이름), 「기록」(입장·점검·시작·종료 자동 기록) |
| Apps Script 스크립트 속성 | 멘토 코드(`MENTOR_CODE`)·운영진 코드(`OPS_CODE`)·연구원 코드(`RESEARCH_CODE`)·Cloudflare TURN 키(비밀값은 여기에만 둡니다) |

영상은 서버를 거치지 않고 브라우저끼리 바로 오갑니다. Apps Script는 연결 정보 몇 줄만 주고받기 때문에 화면이 뜨기까지 **5~7초쯤** 걸립니다.

## 3. 처음 설정 (한 번만)

### 3-1. 구글 시트 + Apps Script 만들기
1. 운영 구글 계정(2026kartsproject@gmail.com)으로 로그인합니다.
2. 구글 드라이브 → **새로 만들기 → 구글 스프레드시트** → 이름을 `무용 온라인멘토링`으로 바꿉니다.
3. 시트 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
4. 기본 `Code.gs` 내용을 모두 지우고, 저장소의 `apps-script/Code.gs` 전체를 붙여 넣은 뒤 **저장(💾)** 합니다.
5. 위쪽 함수 선택 칸에서 **`setup`** 을 고르고 **실행** → 「권한 검토」 → 계정 선택 → **고급 → (안전하지 않음)으로 이동 → 허용**.
6. 아래 **실행 로그**에 `멘토 코드`, `운영진 코드`, `연구원 코드`가 나옵니다. 따로 적어 두세요.
   - 코드를 바꾸려면: 왼쪽 ⚙️ **프로젝트 설정 → 스크립트 속성 → 수정** 에서 `MENTOR_CODE`, `OPS_CODE`, `RESEARCH_CODE` 값을 바꾸고 저장합니다.
7. 시트에 「명단」「기록」 탭이 생겼는지 확인합니다.

### 3-2. 웹앱으로 배포
1. Apps Script 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 유형 선택 ⚙️ → **웹 앱**을 고릅니다.
3. 설정은 다음과 같이 합니다.
   - 실행 사용자: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포**를 누르고, 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
5. 이 URL을 Claude에게 알려 주시면 `config.js`에 넣어 저장소에 반영합니다. 직접 하실 때는 `config.js`의 `API:` 값을 바꾸면 됩니다.

> **나중에 Code.gs를 고칠 때**: 붙여넣기 → 저장 → **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**.
> **「새 배포」는 누르지 마세요.** 주소가 바뀌어 사이트가 끊깁니다.
> 스크립트 속성(코드·TURN 키)만 바꿀 때는 다시 배포할 필요가 없습니다.

### 3-3. 명단 넣기 (시트 「명단」 탭)

| 회차 | 순서 | 시작 | 이름 |
|---|---|---|---|
| 3 | 1 | 17:30 | 홍길동 |
| 3 | 2 | 17:40 | 김민서 |
| test | 1 | | 리허설학생 |

- 이름에는 `발레_`를 붙이지 않습니다(화면에서 자동으로 붙음).
- 명단이 있는 회차는 **명단에 있는 이름만** 입장할 수 있습니다. 명단이 없는 회차는 누구나 이름만으로 입장합니다.
- 운영 화면의 학생 순서·「다음 학생」 버튼은 이 순서를 따릅니다(수정 후 최대 1분 뒤 반영).

### 3-4. GitHub Pages + 도메인(mentoring.kartsproject.com)
1. **가비아** → My가비아 → 도메인 → `kartsproject.com` **DNS 관리** → DNS 설정 → **레코드 추가**
   - 타입 `CNAME` / 호스트 `mentoring` / 값 `kartsproject.github.io.` (끝에 점 포함) → 저장
2. **GitHub** `kartsproject/mentoring` → **Settings → Pages**
   - Source: **Deploy from a branch** / Branch: **main**, 폴더 **/(root)** → Save
   - **Custom domain**: `mentoring.kartsproject.com` → Save
   - 인증서가 발급되면(몇 분~1시간) **Enforce HTTPS**를 체크합니다. **https가 아니면 카메라가 켜지지 않습니다.**

### 3-5. (권장) Cloudflare 무료 중계 서버(TURN)
일부 학생(휴대폰 데이터, 학교·회사 와이파이)은 브라우저끼리 직접 연결이 안 됩니다. 중계 서버를 연결해 두면 이런 학생도 대부분 연결됩니다.
- 무료 한도는 **월 1,000GB**입니다. 한 회차 전체가 중계를 거쳐도 수 GB 수준이라 한도 안에서 충분합니다.

1. https://dash.cloudflare.com 에서 회원가입합니다(운영 구글 계정 이메일 권장). 카드 등록을 요구하는지는 가입 화면 안내를 따르세요. 무료 한도 안에서는 비용이 생기지 않습니다.
2. 대시보드 왼쪽 메뉴 **Realtime**(예전 이름 Calls) → **TURN Server** → **Create**(TURN 앱 만들기)로 이름(예: `karts-mentoring`)을 넣고 만듭니다.
3. 화면에 나오는 **Turn Token ID**와 **API Token**을 복사합니다(API Token은 한 번만 보이니 바로 복사).
4. Apps Script → ⚙️ **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에 아래 두 줄을 넣고 저장합니다.
   - `CF_TURN_KEY_ID` = Turn Token ID
   - `CF_TURN_API_TOKEN` = API Token
5. 편집기에서 `setup`을 한 번 더 실행합니다. 로그에 `TURN 설정: 있음`, `ICE 확인`에 `turn:` 주소가 보이면 완료입니다(다시 배포할 필요 없음).
6. 키를 넣지 않으면 구글 공개 STUN만으로 작동합니다. 이 경우 연결 실패 학생은 ZOOM으로 전환합니다.

## 4. 당일 운영 순서

### 녹화 담당 PC (운영진 1명)
- **크롬**으로 열고, 노트북은 전원에 연결합니다.
- 다운로드 폴더 여유 공간을 확인합니다. 학생 1명(10분)에 약 150~250MB가 필요합니다.
- 운영 화면에 들어가 위쪽 **「이 PC에서 녹화」**를 켭니다(한 사람만). 이 PC가 학생 **연결 점검**도 맡습니다.
- 첫 파일이 저장될 때 크롬이 「여러 파일 다운로드」를 물으면 **허용**합니다.
- 녹화 중에는 **창을 최소화하거나 다른 탭으로 오래 가리지 마세요.** 다른 창을 옆에 띄워 두는 것은 괜찮습니다.

### 학생 안내 (꼭 전달)
- **멘토링 10분 전**에 학생 주소로 들어와 이름 → 녹화 동의 → 카메라·마이크 확인 → 대기실까지 마칩니다.
- 대기실에서 **내 순서(앞에 몇 명·예정 시간)**, 연결 점검 결과, 마이크 막대를 볼 수 있습니다.
- 다음 차례가 되면 「다음 차례입니다」로 바뀌고 멘토와 **미리 연결**됩니다(이때 영상·음성은 아직 보내지 않음). 앞 학생이 끝나는 즉시 멘토링 화면으로 바뀝니다.

### 진행
1. **20분 전**: 운영진이 운영 화면에 입장하고, 녹화 담당이 「이 PC에서 녹화」를 켭니다. 「예비 ZOOM」 칸에 ZOOM 링크를 저장해 둡니다.
2. **멘토**: 멘토 주소와 멘토 코드를 안내합니다. 멘토는 카메라 확인 후 「멘토링실 열기」를 누르고, 그다음은 조작할 것이 없습니다.
   - **사전 논의**: 연구원·운영진이 운영 화면 위쪽 **「화면 등장」**을 누르면 카메라·마이크가 켜지고 멘토 화면에 나옵니다. 마이크·카메라를 각각 끄고 켤 수 있고, 「화면에서 내려가기」로 끝냅니다. 학생 멘토링을 시작하면 자동으로 내려갑니다.
   - 소리 울림을 막으려면 화면에 나오는 사람은 **이어폰**을 쓰고, 같은 방에 있는 다른 사람은 「소리 꺼짐」으로 둡니다.
3. **학생**: 학생 주소(`?r=회차`)를 학생·보호자에게 안내합니다. 학생은 이름 입력 → 녹화 동의 → 카메라 확인 → 대기실 순서로 들어옵니다.
4. 학생이 대기실에 들어오면 녹화 담당 PC가 **자동으로 연결 점검**을 합니다. 운영 화면 학생 목록에 결과가 나옵니다.
   - `직접 연결`: 정상입니다.
   - `중계 연결`: TURN을 거쳐 정상 연결된 상태입니다.
   - `연결 실패`: 그 학생의 **ZOOM** 버튼을 누르면 학생 화면에 ZOOM 입장 버튼이 뜹니다.
5. **시작**: **「다음: ○○ 시작」**을 누르거나, 목록에서 그 학생의 **「시작」**을 누릅니다.
   - 학생 화면이 자동으로 멘토링 화면으로 바뀝니다.
   - 연결되면 **녹화가 자동으로 시작**됩니다.
6. **다음 학생**: 「다음: ○○ 시작」을 누르면 앞 학생은 자동 종료되고, **앞 학생 녹화 파일이 저장**됩니다.
   - 운영 화면 가운데 **「다음 차례 미리보기」**에 다음 학생 카메라가 보이고, 「운영 연결됨」「멘토 미리 연결됨」이 초록이면 바로 넘어갈 준비가 된 것입니다.
7. **마지막 학생**: **「이 학생 종료」**를 두 번(확인) 누르면 녹화 파일이 저장됩니다.
8. 파일 이름은 `3회차_01_홍길동_1732.mp4` 형식입니다(회차_순서_이름_시작시각). 끝나고 드라이브에 올립니다.

### 화면별 정보
- **타이머**: 10분 기준이며, 8분이 지나면 「질의응답」으로 바뀌고 10분을 넘기면 빨간색이 됩니다. 학생·멘토·운영진 화면에 같이 보입니다.
- **학생 공지**: 대기 중인 학생 전체 화면에 안내 문구를 띄웁니다.
- **학생 상태**: 접속/나감, 카메라·마이크 꺼짐, 휴대폰 여부, 완료 시각이 표시됩니다.
- **완료 취소 / 재점검**: 잘못 눌렀을 때나 다시 점검할 때 씁니다.
- **소리 켜짐/꺼짐**: 운영진 PC에서 듣는 소리입니다. 녹화에는 영향이 없습니다.
- **진행 기록 초기화**: 리허설 후에 누릅니다. 명단은 유지되고 진행·점검 상태만 지워집니다.

## 5. 알아 둘 점
- 학생이 **카카오톡에서 링크를 누르면 자동으로 기본 브라우저(크롬·사파리)로 다시 열립니다.** 카카오톡 안에서는 카메라가 안 되는 경우가 많기 때문입니다.
- 지원 브라우저: PC 크롬·엣지, 안드로이드 크롬, 아이폰·아이패드 사파리. **녹화 담당 PC는 크롬**을 씁니다.
- 학생이 새로고침하거나 잠깐 나갔다 와도 같은 이름으로 다시 들어오면 이어서 연결됩니다.
- 운영진·연구원(관람)은 합쳐서 **3~4명 이내**를 권장합니다. 관람자 수만큼 멘토·학생 쪽 전송량이 늘어납니다.
- 연구원 화면에는 녹화·공지·ZOOM·학생 시작 버튼이 없습니다(보기와 화면 등장만 가능).
- 녹화 파일은 크롬에서 **MP4**로 저장됩니다(일부 브라우저는 WebM).
- 기존 웹 대기실(b_apply)과는 별개 시스템입니다. 3회차는 ZOOM을 예비로 둔 채 시범 운영하는 것을 권장합니다.
- 「기록」 탭에 입장·점검·시작·종료 시각이 자동으로 쌓여 운영 시수 집계에 쓸 수 있습니다.
